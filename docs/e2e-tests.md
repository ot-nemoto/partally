# E2Eテスト一覧と検証結果

partally に必要な E2E（ブラウザを通した）テストの一覧と、実環境で試した結果をまとめる。機能のルールは [機能仕様書](spec.md)、開発の手順は [開発ガイド](development.md) を参照。

E2E は `e2e/tests` に Playwright で実装している（#193）。今は P0 の 12 本を `e2e/tests/p0.spec.ts` に、P1 のうち実装したもの（「実装済み」と書いたもの）を `e2e/tests/p1.spec.ts` に、CSP を効かせた確認（5 章）を `e2e/tests/csp.spec.ts` に置き、`npm run e2e` で実行する。CI（`.github/workflows/ci.yml`）の `e2e` ジョブでも実行し、通らないと本番へデプロイしない。P1 の残りと P2 は未実装。

## 1. 前提：既存テストとの分担

E2E 以外の自動テストは次の範囲をカバーしているため、E2E では重複させない。

| 既存テスト | カバー範囲 |
|---|---|
| `api/src/app.*.test.ts` | 認証（1 台の端末で複数の参加者を含む）・管理者ログインの制限と Cookie・写真（アップロードの上限を含む）・お気に入り・ゲーム6形式・ラウンド・景品・スケジュール・イベント終了・CloudFront を通ったかの確かめ・CSP の報告の API 統合テスト（メモリ内リポジトリ） |
| `infra/test/*.test.ts` | CDK のスタック（リソース・応答のヘッダ・権限）と、ワークフローの決まり（アクションの指定の仕方など） |
| `api/src/scoring.test.ts` | ポイント・順位・同点処理の計算 |
| `packages/shared/src/*.test.ts` | game-rules、景品の順位、データ移行の ZIP（data / prize / game archive、schedule-file） |
| `web` の単体テスト | StatusFilter と i18n のみ（画面の流れは E2E で確かめる） |

E2E の対象は、API テストでは検証できない次のものに限る。

1. 実ブラウザの画面遷移・表示・入力（SPA のルーティング、ダイアログ、ドラッグ操作）
2. 複数アクター・複数端末の連携（幹事の操作が参加者の画面にどう届くか、その逆）
3. Cookie・セッション・localStorage・IndexedDB などブラウザの状態
4. ファイルの実アップロード／ダウンロード（写真、景品・ゲームの画像、ZIP 移行、QR 印刷）
5. 時間・ポーリング依存の挙動（ゲーム開催の5秒ポーリング、スケジュールの「いま／つぎ」の30秒更新、写真の30秒再送）
6. オフライン・通信断からの復旧

優先度は、P0 = イベント当日に壊れると進行が止まる、P1 = 主要機能の連携、P2 = あると安心、とする。

## 3. P1：主要な連携（約31本）

### 参加・認証

- 無効な QR トークンでは登録に進めない
- 暗証番号を5回間違えてロック → 幹事が解除すると別端末でログインできる（ログイン中の端末は使える）
- 紐づけ解除 → 解除された参加者は次の操作でログアウトし、同じ QR で新規登録できる（ポイントは引き継がない）。その端末でほかの参加者も覚えていれば、ログアウトせずにその人に切り替わる
- 未ログインで参加者・管理画面の URL を直接開くと、それぞれ案内・ログインへ戻る

### 1 台の端末で複数の参加者（U-9。`e2e/tests/p1.spec.ts` で実装済み）

- 同じ端末で 2 人を登録すると、上に名前のボタンが並び、今の人に色が付く。押すとその人に切り替わり、ホーム以外の画面（みんなの写真）でも同じ画面のまま切り替わる。覚えている人の QR を読み込むと、暗証番号を聞かれずにその人になる
- 送信待ちの写真は、ほかの人に切り替えた後に送られても、撮った人の写真になる
- 使っていない人の紐づけを解除してからその人のボタンを押すと、案内が出てボタンが消える。使っている人の紐づけを解除すると、画面を開いたまま覚えているほかの人に切り替わり、残りが 1 人ならボタンが消える

### 写真

- HEIC の写真を投稿できる（変換に失敗したときは元の画像を送らずエラーを出す）
- 大きい写真が縮小され、一覧（サムネイル）と拡大（本体）で表示される
- オフラインで投稿 → 送信待ちがホームに出て、オンラインに戻ると自動で送られる（「今すぐ再送」でも送れる）
- 即時公開（設定 `post`）では承認なしで公開されポイントが入る。切り替えは後の投稿にだけ効く
- 却下 → 投稿者に「非公開」と出る。公開中の写真を削除 → 自分の写真からも消え、お気に入りとポイントが戻る
- 確認待ちの写真は、投稿者本人と幹事以外には見えない

### ゲーム共通・形式別・ラウンド

- 開催中は別のゲームを開始できない（1問とラウンドで共通）
- 中断しても答えは残り、再開始しても答え直しできない
- 終了を取り消すとポイントが消え、もう一度終了するとその時刻で入り直す
- 参加者が画面を開いたまま、開始でお知らせが出て、終了で消える（再読み込みなし）
- 数値予想：正解の数を入れないと終了できず、理由が出る。終了後は近い順の点数と「2位（予想42）+5」の形でホームに出る
- 投票：名前・二つ名で絞り込め、自分には投票できない。参加者には票数と投票先が見えず、幹事には集計が見える
- 合言葉：不正解なら何度でも試せる。表記ゆれ（パーティー／ぱーてぃー）でも正解になる。正解後は送れない
- 抽選：「参加する」は1回だけ。終了で当選が決まり、終了の取り消しでは引き直しの注意が出る
- ラウンド：開始するとお知らせに「N問中M問回答済み」が出て、全問が番号順に並ぶ。1問ずつ答え、一括で終了すると全問同じ時刻でポイントが入る。ラウンドの中のゲームは単独で開始・終了できない

### 公開・設定・移行・言語

- ランキング・推移・景品・スケジュール・ゲーム結果の公開を個別に切り替えると、参加者の「イベント情報」の出し分けが変わる。オフのものは API からも返らない
- 名前を伏せる（全員 `???`）・ポイントを伏せる（数字なしで棒と線の形だけ）が参加者の画面に効く
- スケジュールのドラッグ編集（上下で開始時刻、下の端で長さ、左右で列）と、列の表示／非表示（非表示の列は参加者に出ず、「いま／つぎ」も表示項目だけで決まる）
- ポイントの点数を変えると、全員の表示ポイントが再計算される（ホーム・ランキング・幹事のユーザ一覧で一致する）
- ポイントを伏せる／ゲームの点数を伏せる設定がホームに効き、幹事には見える
- データの移行：ZIP を書き出し、空の環境へ取り込むと、ゲーム（ラウンドの再現を含む）・景品（画像を含む）・スケジュール（見せない列と日付）・設定が戻る
- 日本語／English の切り替えがその場で効き、再読み込み後も保たれる。幹事や参加者が入れた内容と二つ名は訳されない
- スマートフォンの幅で、主要な画面（ホーム／ギャラリー／ゲーム／イベント情報）が崩れず操作できる

## 4. P2：あると安心（約20本）

- 幹事が暗証番号を消した参加者は、次に別端末で読み込んだときに決め直す流れになる
- 幹事による名前・二つ名の変更が参加者の表示に反映され、二つ名は重ならない
- 送信を5回断られた写真は破棄され、撮り直しの案内が出て、後ろの写真が詰まらない。アップロードの上限（確認待ちの枚数・短い間の回数）で断られたものは回数に数えず、写真を残す
- お気に入りの上限を下げても選択済みは残り、上限を下回るまで新しく選べない
- 開催中・終了後のゲームの編集でポイントが計算し直される。幹事のプレビューでは答えを試せるが保存されず、点数・正解・合言葉は出ない
- 画像付きのクイズ（問題と選択肢）で、選択肢が画像付きの大きいボタン（2列）になる
- 結果入力の人選びで、検索・複数選択・全員の選択と解除ができ、他の枠の人を選ぶと枠が移る
- 終了できない問題を含むラウンドは、終了が止まって問題ごとの理由が出る
- ゲームの結果の公開で、正解・自分の答えと結果・入った人が終了した順に出る（点数は出ない）。イベント終了の後に終了したゲームには「ポイントには数えていません」と付く
- 同じポイントのときの順位の優先順を並べ替えると、同点の人の順位が変わる
- 不正な ZIP は何も取り込まず理由が出る。以前の形式（景品・ゲームの ZIP、スケジュールの JSON）も取り込める
- 以前の URL（`/quiz` → `/game`、`/favorites` → `/gallery`、`/admin/quizzes` → `/admin/games`）が移転する
- QR の印刷ページを印刷（PDF化）しても、QR と通し番号と日英の案内が欠けない

## 5. CSP を効かせた主な流れ（`e2e/tests/csp.spec.ts` で実装済み）

本番では読み込み元を絞る CSP（`infra/lib/csp.ts` の `reportOnlyCsp()`）を Report-Only で付けている（#227）。同じ値を CloudFront の代わりに画面の応答へ `Content-Security-Policy` として付けて（強制にして）、次の流れで違反が出ず、動くことを確かめる。開発用のサーバ（Vite）はインラインのスクリプトを入れるので、本番と同じビルドの画面（`vite preview`）を開く。

- 参加者：QR からの登録、写真の投稿（JPEG と HEIC。HEIC は heic2any で JPEG に変換してから送る）、ギャラリー（`/photos` の画像）、ホーム・自分の写真・ゲーム・イベント情報
- 管理画面：ログイン、各画面、データの書き出し（ZIP）、QR の印刷ページ（`data:` の画像）

## 6. E2E でやらないもの

- ポイント計算・順位付け・同順位の処理の組み合わせ → `api/src/scoring.test.ts`
- 順位の範囲の重なりや逆転などの入力の検証、形式ごとの終了の条件 → API の統合テストと `packages/shared`
- 合言葉の表記ゆれの網羅、投票・数値予想の同点の順位の計算 → API の統合テストと `packages/shared`
- データ移行の ZIP の中身の形式の検証 → `packages/shared` の archive のテスト
- DynamoDB・S3・署名の実装 → `dynamo-repository`・`photo-storage`・`url-signer` のテスト
- 本番 AWS 固有の部分はローカルでは再現しないため、デプロイの後やリハーサルの手動確認に残す。次のものがある
  - CloudFront の署名付き Cookie・URL と、応答のヘッダ（セキュリティのヘッダ・CSP）が実際に付くこと（CSP の値で画面が動くことは 5 章で確かめる）
  - `X-Origin-Verify`（API Gateway の URL を直接開くと 403 になる）
  - S3 への署名付き POST、S3 のイベントによる取り込みと JPEG の確かめ（流れ自体は API の ingest・upload-limit のテストで担保する）
  - 管理者ログインの接続元ごとの数え方（`CloudFront-Viewer-Address`。数え方の決まりは API の admin-login のテストで担保する）
  - SSM の値（管理者パスワードなど）の読み直し（読み直しの決まりは `cached-value` のテストで担保する）
- 管理者パスワードを変えたときに、前のパスワードでのログインが切れること → `app.admin-session.test.ts`

## 7. 実装の作り

2026-11-19 の試行（8章）から得た決め事と、それに沿った今の作り。

- 道具は Playwright（`e2e` ワークスペース、`@playwright/test`）。幹事と参加者A・Bを別々の BrowserContext で同時操作でき、モバイル幅・オフライン・ダウンロードの検証が1つで足りるため。参加者はスマホの大きさ（390×844）、幹事は PC の大きさで開く
- ローカル開発環境（メモリ内の API `api/src/dev.ts` と web の Vite）に対して実行し、本番 AWS には流さない。`playwright.config.ts` の `webServer` で両方と、CSP の確認に使う本番と同じビルドの画面（`vite preview`、ポート 4173）を起動する（API と Vite は、手元で起動済みなら使い回す。`vite preview` は古いビルドで確かめないよう、毎回ビルドし直して起動する）
- API は1つで、データはテストの間で共有する。そのためテストは1つずつ順に実行し（`workers: 1`）、各テストは自分で作ったデータだけを見る。開催中のゲーム・ラウンドは、テストのたびに `afterEach` で止めて次のテストに持ち越さない
- 準備（QR の発行・参加者の登録・ゲームの作成・設定の変更）は API を直接呼んで作り、検証したい流れだけを画面から操作する。`e2e/tests/helpers.ts` の `adminApi()`（幹事の API）・`participant()`（登録済みの参加者のブラウザ）・`adminPage()`（ログイン済みの幹事のブラウザ）・`updateSettings()` を使う
- 確認ダイアログは、画面内の確認ダイアログ（`web/src/components/ConfirmDialog.tsx` の `confirmDialog()`）で出す（#194 で `window.confirm()` から置き換えた）。テストでは `acceptConfirm()` で「OK」を押し、確認を承認して進む流れとして確かめる
- 写真・景品の画像は、実ファイルのアップロードで検証する。画像は `jpeg()` でブラウザの canvas から作る。HEIC は `e2e/fixtures/sample.heic` を使う（`e2e/fixtures/make-heic.py` で ffmpeg から作ったもの。外から見本を持ち込まない）
- CI では `e2e` ジョブで Chromium を入れて実行し、失敗したら HTML のレポートを成果物として残す

## 8. 実環境での試行結果（2026-11-19）

検証用の本番相当の環境（検証後にリセット予定、当時の登録 88 名・既存の検証データあり）で、P0 を中心にブラウザ操作で試した結果。ブラウザの自動操作で実施し、自動操作では進めなかった操作は幹事本人の手動操作で切り分けた。

| 項目 | 結果 | 確認した内容 |
|---|---|---|
| 参加者トップ（未ログイン） | PASS | 見出しの「partally」と「配布された QR コードをスマホのカメラで読み込んでください。」が表示された |
| 幹事ログイン | PASS | 管理画面（User）に到達。パスワードだけのログインのため、パスワードの保管カードは使えず、本人がブラウザを一時的に操作して入力した |
| QR 発行 | PASS | 5件を発行し、全体 100 → 105 件、未使用 12 → 17 件になった |
| 参加者の登録（P0-1） | PASS | 名前と暗証番号で登録し、二つ名付きの表示名でホームに表示された |
| 同じ端末での再ログイン（P0-2） | PASS | 同じ QR のリンクを開くと、暗証番号なしでホームへ入れた |
| クイズの回答（P0-6 の前半） | PASS | 開催中だったクイズで、お知らせから開いて回答し、「対応済み」が出て答え直しできなかった。幹事側の集計にも反映された |
| クイズの終了 → ポイント（P0-6 の後半） | PASS（手動で切り分け） | 自動操作では終了ボタンが無反応だったが、手動のクリック1回で終了し、参加者のホームに点数 10 と「テスト あ +10」が出た。もう1問も開始・回答・終了でき、合計 20 点と授与の行2件を確認した |
| イベント終了（P0-12） | PASS（手動で切り分け） | 手動で終了すると、参加者に「イベントは終了しました。ポイントの集計は終わりました。」が出て、管理画面は「終了を取り消す」に変わった。終了の取り消しの操作自体は実施していない（イベントは終了したまま残した） |
| 景品・ランキングの公開（P0-9, P0-10 の一部） | PASS | 景品を作成して1位に割り当て、公開すると参加者のイベント情報にランキングと景品が出た |

### 試行で分かったこと

- **自動操作で進めなかった操作は、どれも `window.confirm()` で確認するもの**だった（ゲームとラウンドの終了・中断・取り消し・削除、イベントの終了・取り消し）。自動操作ではダイアログもモーダルも表示されず、エラーも出ず、状態が変わらなかった。コードでも、確認が通らなければ処理を中断して API を送らない作りになっている（`web/src/pages/admin/AdminGames.tsx`、`AdminSettings.tsx`、`games/Rounds.tsx`）。手動ではすべて正常に動いたため、アプリの不具合ではないと判断した。改修の Issue は #194（対応済み。画面内の確認ダイアログに置き換えた）
  - ただし QR の発行も `confirm()` で確認する（`AdminTokens.tsx`）のに、試行では自動操作で発行できている。`confirm()` だけが原因とは言い切れず、QR の発行で確認がどう扱われたか（ダイアログが出て承認されたのか）は確かめていない。#194 の置き換え後は、E2E では画面内の確認ダイアログで「OK」を押して進む
  - `confirm()` はほかに、ユーザの紐づけ解除・暗証番号のロック解除・消去（`AdminUsers.tsx`）、写真の削除（`AdminPhotos.tsx`）、景品の削除（`AdminPrizes.tsx`）、スケジュールの項目の削除（`AdminSchedule.tsx`）、データの取り込みの確認（`data/DataImportDialog.tsx`）で使っている。試行では触っていないが、同じく自動操作では止まるおそれがあったため、#194 でまとめて置き換えた
- **管理画面の一覧が、保存や操作の直後には古いまま**。ゲームの回答数（「更新」を押しても変わらず、再読み込みで変わった）、作成した景品とスケジュールの項目（再読み込みで出た）で確認した。Issue は #195（対応済み。一覧の読み込みが追いつくまで、保存した内容を画面に重ねて出す）
- **登録完了画面の二つ名の文字色が薄く**、背景とほぼ同化して読みにくい。Issue は #196（対応済み）
- **QR のトークンの文字列が管理画面に出ない**。一覧も印刷ページも QR の画像だけで、参加リンクの URL をコピーする手段がなかった（試行では QR の画像を読み取って URL を得た）。Issue は #197（対応済み。参加リンクのコピーを付けた）
- ランキングの「名前を伏せる」は、設定を触る前の時点でオンだった。試行の途中で自動的にオンになったように見えたが、既存の設定だった可能性を否定できず、不具合とは判断していない
