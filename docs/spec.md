# 機能仕様書

partally の各機能が「何を・どう動かすか」を、利用者から見たルールとして定める。仕組み（構成・データモデル・API）は [設計書](design.md)、使い方は [README](../README.md) と [幹事向けガイド](organizer-guide.md) を参照。

各要件の番号（U-1 など）は、Issue・PR・設計書から参照するために使う。

---

## 1. 前提

- 忘年会などの余興イベントで、参加者 80 名程度・1 イベントでの利用を想定する。
- 参加者はスマートフォンのブラウザ、幹事は PC またはスマートフォンのブラウザで使う。アプリのインストールは不要。

### 1.1 登場人物

| 人 | すること |
|---|---|
| 参加者 | QR コードで参加し、写真の投稿・お気に入り・ゲーム（クイズ・数値予想・投票・合言葉）への回答をする |
| 幹事（管理者） | 管理画面で、QR コードの発行、写真の確認、ゲーム・景品の準備と進行、設定をする |
| 運用担当者 | デプロイと本番データの初期化をする（[初期設定・デプロイ手順](setup.md)） |

### 1.2 画面

| 参加者の画面 | 内容 |
|---|---|
| ホーム | 表示名、ポイントとその内訳（ゲームで点数が入ったものも）、ポイントのルール、お気に入りの選択数、撮影・写真の選択 |
| みんなの写真 | 公開中の写真の一覧と拡大表示、お気に入りの付け外し |
| 自分の写真 | 自分が投稿した写真と状態（確認待ち・公開中・非公開） |
| イベント情報 | スケジュール・ランキング・ポイントの推移・景品（幹事が公開したものだけ） |
| ゲーム | 開催中のゲームの説明と、クイズ・数値予想・合言葉への回答、投票、結果入力の枠と点数 |

| 管理画面 | 内容 |
|---|---|
| QR | QR コードの発行・印刷 |
| User | 参加者の一覧、名前・二つ名の変更、紐づけ解除 |
| Ranking | ランキングと、順位の移り変わりの再生 |
| Trend | ポイントの推移のグラフ |
| Photo | 写真の確認（承認・却下）・削除 |
| Game | ゲーム（クイズ・数値予想・投票・合言葉・結果入力）の作成・開催・確定、結果入力の人の選択 |
| Prize | 景品の登録と、渡す順位の割り当て |
| Schedule | スケジュール（進行表）の作成 |
| Setting | ポイント・公開方法・参加者に見せるものの設定 |

## 2. 参加・ログイン

| # | 要件 |
|---|---|
| U-1 | 幹事が個別の QR コードを発行して配布する。QR コードには推測できないランダムな値を埋め込み、通し番号（001, 002, …）を付ける。1 回に発行できるのは 200 件まで |
| U-2 | 初めて QR コードを読み込んだときは名前（1〜20 文字）だけを入れ、QR コードと参加者を紐づける |
| U-3 | 同じ名前の人を見分けられるよう、全員に重ならない「二つ名」（例: 疾風の魔術師）を自動で付ける。表示名は `〈二つ名〉名前` |
| U-4 | 紐づけた後は、同じ QR コードを読み込むだけでログインできる |
| U-5 | ログインは 30 日間続く。幹事のログインは 12 時間で切れる |
| U-6 | 名前・二つ名は幹事だけが変えられる。二つ名は全員で重ならないものにする |
| U-7 | QR コードと参加者の紐づけ解除は、幹事だけが管理画面から行える |

- 名前・二つ名（と景品名）は、全角英数を半角に、半角カナを全角にそろえ（Unicode の NFKC 正規化）、前後の空白を除き、続いた空白を 1 つにする。
- 紐づけ解除をすると、その参加者は次の操作でログアウトし、同じ QR コードではその人としてログインできなくなる。
  - 解除した QR コードは未使用に戻り、読み込んだ人が新しい参加者として登録できる（QR コードを使えなくする機能はない）。
  - 解除した参加者の写真は残り、投稿者の表示も残る。ランキングでは、管理画面には「解除済み」として薄く表示し、参加者の画面と景品の順位には数えない。
  - 解除した参加者のポイントは、新しく登録し直しても引き継がない。
  - 解除した参加者が選んでいたお気に入りは外れずに残り、選ばれた人のポイントもそのまま残る。解除した参加者の写真も公開されたままで、ほかの参加者がお気に入りに選べる。

## 3. 写真

| # | 要件 |
|---|---|
| P-1 | 参加者はその場で撮影するか、端末の写真を選んで投稿できる |
| P-2 | 公開された写真は参加者全員が見られる |
| P-3 | 投稿者を記録し、参加者ごとに投稿数・公開数を数える。投稿数は確認待ちと公開中の写真の数で、却下・削除された写真は数えない |
| P-4 | 写真の削除は幹事だけができる |
| P-5 | 写真の公開方法は設定で選ぶ。「管理者が承認してから公開」（既定）では幹事が承認するまでほかの参加者に見えない。「アップロードと同時に公開」では投稿してすぐ公開される |
| P-6 | iPhone の HEIC 形式の写真も投稿できる |

- 投稿する写真は、端末で縮小（長辺 1600px）して JPEG にしてから送る。位置情報などの撮影情報は消える。
- 電波が悪くて送れなかった写真は端末に残し、30 秒ごとと、電波が戻ったときに自動で送り直す。送信エラーのときは「今すぐ再送」で送り直せる。サーバに 5 回断られた写真と、端末に残した写真が読めなくなったもの（1 回目で）は捨て、撮り直しを案内する。
- 写真の状態は「確認待ち」「公開中」「却下」。却下と削除は幹事が行い、どちらも元に戻せない。
  - 却下した写真は、投稿者の「自分の写真」に「非公開」と表示する（写真そのものは消す）。
  - 削除した写真は、「自分の写真」からも消える。
  - 公開中の写真を削除すると、その写真へのお気に入りもすべて外れ、関係するポイントも戻る。
- 確認待ちの写真は、投稿者本人と幹事だけが見られる。
- 公開方法を変えても、これから投稿される写真にだけ効く。

## 4. お気に入り

| # | 要件 |
|---|---|
| F-2 | 参加者は公開中の写真からお気に入りを選べる。自分の写真は選べない |
| F-3 | 1 人が選べる枚数は設定で決める（既定 10 枚、0〜100）。上限の中で自由に付け外しできる |
| F-5 | お気に入りの受付は設定でオン・オフできる。オフの間は追加も解除もできない（締め切り）。付いたポイントは残る |

- 上限を減らしても、選択済みのお気に入りはそのまま残る。上限を下回るまで新しく選べない。
- 選んでいる枚数と上限は、ホームと「みんなの写真」に表示する。

## 5. ポイント

| # | 要件 |
|---|---|
| F-1 | 写真が公開されると、投稿した人にポイントが入る（1 枚あたり既定 1 ポイント） |
| F-4 | お気に入りに選ばれた人にポイントが入る（1 回あたり既定 1 ポイント）。お気に入りを選んだ人にもポイントが入る（1 枚あたり既定 10 ポイント）。外すと両方とも戻る |
| K-5 | ゲームを確定すると、クイズは選んだ選択肢の点数、数値予想は正解に近い順の順位に応じた点数、投票は得票の順位に応じた点数（と投票した人の点数）、合言葉は正解した順に応じた点数、結果入力は選ばれた人にその枠の点数が入る |

```
ポイント = 公開中の写真の数 × 写真 1 枚のポイント
        + お気に入りに選ばれている数 × 選ばれたときのポイント
        + お気に入りに選んでいる数 × 選んだときのポイント
        + 確定したゲームの点数の合計（クイズは選んだ選択肢、数値予想・投票・合言葉は順位が入る範囲、投票した人の点数、結果入力は入った枠の点数）
```

- それぞれの点数（0〜100）は設定で決める。点数を変えると、それまでの分も含めて全員のポイントが新しい点数で計算し直される。ゲームの選択肢・枠・順位の範囲・投票した人の点数や、数値予想の正解の数、合言葉を直したときも同じ。
- 却下・削除された写真、外したお気に入り、削除された写真へのお気に入りは数えない。
- 下書き・開催中のゲームは数えない（クイズを選び直して点数の変化から正解を探れないようにするため）。
- 参加者のホームにポイント・ゲームの点数を表示するかは、設定でそれぞれ決める（既定はどちらも表示）。
  - ポイントを伏せている間は、ポイント・お気に入りに選ばれた数・写真ごとの ♥ の数を参加者に見せない。
  - ゲームの点数を伏せている間は、ゲームの点数と、点数が入ったもの（入った枠・選んだ答え）を見せない。
  - 伏せている間も集計は続き、管理画面では見られる。
  - この 2 つの設定はホーム（と写真の ♥ の数）だけに効く。参加者にランキング・推移を見せているときは、そちらの「ポイントを伏せる」をオンにしない限り、全員のポイントが見える（推移の線の上がり方から、ゲームの点数も分かる）。

## 6. ゲーム

クイズやじゃんけん大会のような余興で、参加者にポイントを付ける。ゲームは作るときに形式を選ぶ（後から変えない）。

| 形式 | 参加者がすること | ポイント |
|---|---|---|
| クイズ | 開催中に、選択肢から 1 つ選ぶ（確定までは選び直せる） | 選んだ選択肢の点数 |
| 数値予想 | 開催中に、数（0〜100 の整数）を予想して答える（確定までは答え直せる） | 正解に近い順の順位が入る範囲の点数 |
| 投票 | 開催中に、参加者全員の中から 1 人に投票する（確定までは選び直せる） | 選ばれた人に、得票の順位が入る範囲の点数。投票した人にも決めた点数 |
| 合言葉 | 開催中に、会場で見つけた合言葉を入れる（不正解なら何度でも） | 正解した順（先着順）が入る範囲の点数 |
| 結果入力 | アプリの外で遊ぶ（じゃんけん大会など） | 幹事が枠（優勝など）ごとに選んだ人に、枠の点数 |

### 6.1 共通

| # | 要件 |
|---|---|
| K-1 | 幹事がゲーム（名前 1〜50 文字、説明 0〜500 文字・改行可、画像 1 枚は任意）を作る。クイズ・数値予想では説明と画像が問題になる |
| K-2 | 幹事のタイミングで開催する。開催中にできるのは形式によらず 1 つだけ |
| K-3 | 開催中は、参加者のほかの画面の上部にお知らせ（クイズ・数値予想は「問題が出ています」、投票は「投票受付中」、合言葉は「合言葉を受付中」、結果入力は「ゲーム開催中」）を出し、ゲームの画面へ案内する。開催・確定は参加者の画面に自動で反映される（画面を開いている間、5 秒ごとに確認） |
| K-4 | ゲームの画面には、名前・説明・画像と、クイズなら選択肢、数値予想なら数の入力欄と順位の範囲ごとの点数、投票なら選べる人の一覧と順位の範囲ごとの点数、合言葉なら入力欄と正解した順の範囲ごとの点数、結果入力なら枠と点数を出す（誰がどの枠に入ったか、選択肢の点数、数値予想の正解、誰が誰に投票したか、合言葉は出さない） |
| K-5 | 幹事が「確定」すると、確定した時刻でポイントが入る |
| K-6 | 参加者のホームに、自分のゲームの点数と、点数が入ったもの（例: じゃんけん大会 優勝 +30、第 1 問 北海道 +10、飴の数 2 位（予想 42） +5）を見せる。見せるかは設定で決める（既定は見せる） |

- 状態は「下書き」→「開催中」→「確定」。下書きから直接確定もできる。
  - 「開催をやめる」で開催中から下書きに戻せる（クイズ・数値予想・投票・合言葉の答えは残る）。
  - 「確定を取り消す」で確定から下書きに戻すと、入ったポイントも消える。もう一度確定すると、その時刻で入る。
- 名前・説明・点数・選択肢や枠の文言・選んだ人は、開催中・確定した後も直せる。直すとポイントは直した内容で計算し直し、推移では確定した時刻のまま。
- ゲームの削除は、開催中でなければできる。確定済みなら入ったポイント、クイズ・数値予想・投票・合言葉なら答えも消える。
- 画像は景品と同じく、端末で縮小（長辺 1200px）して JPEG にしてから登録する。差し替える・外す・ゲームを削除すると、古い画像はすぐに見えなくなる。参加者には開催中のゲームの画像だけを見せる。
- 管理画面の一覧は、新しいゲームを上にし、作成順の番号（第 N ゲーム）を付ける。開催中・下書き・確定ごとに表示・非表示を選べる（そのブラウザに覚える）。

### 6.2 クイズ

| # | 要件 |
|---|---|
| Q-1 | 選択肢（2〜10 個、各 1〜100 文字）ごとに点数（0〜100）を決められる。選択肢ごとに画像も 1 枚付けられる（任意。付けても文字は必要） |
| Q-2 | 参加者は開催中に選択肢を 1 つ選んで答える。確定するまでは選び直せる |
| Q-3 | 確定した時点の答えで、選んだ選択肢の点数がポイントに入る。正解はアプリに出さず、司会が発表する |

- 選択肢を増やす・減らすのは、まだ答えが無い下書きの間だけ。
- 画像のある選択肢は、参加者の画面で画像を大きく出したボタン（2 列）にする。
- 確定の直前に送った答えが、確定より後に届いた場合は数えない。
- 参加者には選択肢の点数を見せない。幹事は、選択肢ごとの回答数と、誰がどれを選んだかを見られる。

### 6.3 結果入力

| # | 要件 |
|---|---|
| R-1 | 枠（名前 1〜30 文字・点数 0〜100、20 個まで）を決める。例: 優勝 30 / 準優勝 20 / ベスト 4 10、または「勝ち残り 10」の 1 つだけ。名前だけで作り、枠は後から足してもよい |
| R-2 | 枠ごとに、そこに入る参加者を選ぶ。1 つの枠に何人でも入れられ、1 人は 1 つのゲームで 1 つの枠にだけ入る |

- 枠が 1 つも無いゲームは確定できない。
- 人を選ぶ画面では、名前・二つ名・QR の通し番号で絞り込み、チェックで複数選ぶ。全員を選んでから負けた人を外す選び方もできる。紐づけを解除した人は選べない（選んだ後に解除された人は、枠に残り、ポイントも残る）。
- ほかの枠に入っている人を選ぶと、その枠から移る。

### 6.4 数値予想

| # | 要件 |
|---|---|
| N-1 | 順位の範囲（例: 1〜1 位 10 点 / 2〜5 位 5 点 / 6〜10 位 2 点、20 個まで。順位は 1〜1000、点数は 0〜100）を決める。範囲は重ならないようにする |
| N-2 | 参加者は開催中に数（0〜100 の整数）を 1 つ答える。確定するまでは答え直せる |
| N-3 | 幹事が正解の数（0〜100 の整数）を入れて確定すると、正解との差が小さい順に順位を付け、順位が入る範囲の点数がポイントに入る |

- 正解との差が同じ人は同じ順位にする（例: 差 0・5・5・7 なら 1 位・2 位・2 位・4 位）。どの範囲にも入らない順位は 0 点。
- 正解の数は作るときに決めなくてもよく、確定するまでに入れる。正解の数か範囲が無いゲームは確定できない。確定した後に直すと、順位と点数も数え直す（確定したまま正解の数や範囲を全部外すことはできない。外すなら先に確定を取り消す）。
- 参加者には順位の範囲と点数を見せ、正解の数は見せない。幹事は、誰が何を答えたかと、正解の数があれば順位・差・点数を見られる。
- 確定の直前に送った答えが、確定より後に届いた場合は数えない。

### 6.5 投票

| # | 要件 |
|---|---|
| V-1 | 得票の順位の範囲（数値予想と同じ形。例: 1〜1 位 30 点 / 2〜3 位 10 点）と、投票した人に入る点数（0〜100、0 なら入らない）を決める |
| V-2 | 参加者は開催中に、参加者全員（自分と、紐づけを解除した人を除く）の中から 1 人を選んで投票する。名前・二つ名で絞り込める。確定するまでは選び直せる |
| V-3 | 確定すると、票の多い順に順位を付け、選ばれた人に順位が入る範囲の点数、投票した人に投票した人の点数が入る |

- 同じ票数の人は同じ順位にする（例: 5・3・3・1 票なら 1 位・2 位・2 位・4 位）。0 票の人と、どの範囲にも入らない順位は 0 点。
- 範囲が無いゲームは確定できない。確定したまま範囲を全部外すことはできない（外すなら先に確定を取り消す）。
- 投票した後に紐づけを解除された人への票・その人の票は、そのまま数える。
- 選べる人の一覧は、ゲームの画面を開いたときとアプリに戻ったときに読む（「一覧を読み直す」でも読める）。投票の間は、ランキングの「名前を伏せる」の設定にかかわらず、参加者の名前・二つ名を一覧に出す。
- 参加者には、誰が誰に投票したかと途中の票数は見せない。幹事は、票の多い順に順位・票数・点数と、誰が投票したかを見られる。
- 確定の直前に送った票が、確定より後に届いた場合は数えない。

### 6.6 合言葉

| # | 要件 |
|---|---|
| W-1 | 合言葉（1〜50 文字）と、正解した順の範囲（数値予想と同じ形。例: 1〜3 番目 10 点 / 4〜100 番目 3 点）を決める |
| W-2 | 参加者は開催中に言葉を入れて送り、その場で正解か不正解かが分かる。不正解なら何度でも試せる。正解した後は送れない |
| W-3 | 確定すると、正解した人を正解した時刻の順に並べ、順番が入る範囲の点数が入る |

- 比べるときは、全角・半角、大文字・小文字、カタカナ・ひらがな、空白の違いをなくす（「パーティー」「ぱーてぃー」「ﾊﾟｰﾃｨｰ」は同じ）。
- 不正解の言葉は残さない。正解した後にもう一度送っても、最初に正解した時刻のまま。
- 範囲が無いゲームは確定できない。確定した後に合言葉を直すと、今の合言葉に合う答えだけで数え直す（合わなくなった人は、開催し直せばもう一度答えられる）。
- 参加者には合言葉を見せない。幹事は、正解した順に名前・入れた言葉・時刻・点数を見られる。
- 確定の直前に送った答えが、確定より後に届いた場合は数えない。

## 7. ランキング・推移

| # | 要件 |
|---|---|
| F-6 | 参加者にもランキングとポイントの推移を見せられる。見せるか（既定は見せない）と、名前・ポイントを伏せるかは、設定でそれぞれ決める。合計と順位は、写真・お気に入り・ゲームのすべてのポイントで出す |
| F-7 | 合計が同じ人の順位は、設定で決めた優先順（各項目のポイントと登録順）で比べて分ける。同じ順位の人は出ない |

### 7.1 順位の付け方

1. 合計ポイントの高い順に並べる。
2. 合計が同じ人は、設定の「同じポイントのときの順位」の順に比べて上下を決める。順位の数字も分ける。
   - 項目は「写真のアップロード」「お気に入りを選んだ」「お気に入りに選ばれた」「ゲーム」「登録順」の 5 つ。既定はこの順。
   - 以前あった「クイズ」の項目は、保存済みの設定を読み込むときに取り除く。
   - 項目を後から加えたときは、保存済みの設定の「登録順」の前に入る（登録順で必ず差が付くので、後ろに入れると比べられることがない）。
   - ポイントの項目は、その項目のポイントが多い人を上にする。項目のポイントは、5 章の計算式のうちその項目の分（例: 写真のアップロードなら、公開中の写真の数 × 写真 1 枚のポイント）。
   - 登録順は、先に登録した人を上にする。
3. 登録順で必ず差が付くので、同じ順位の人は出ない（1 位、2 位、3 位…と 1 人ずつ）。
4. 参加者の画面では紐づけを解除した人を除き、上から 1 位、2 位…と順位を付け直す。

### 7.2 管理画面

- **Ranking**: 順位・表示名・ポイントと、ポイントに比例した横棒（1 位が最長）を出す。紐づけを解除した人は薄く表示する。
  - 「推移を再生」で、最初にポイントが入る少し前から今までの順位の移り変わりを、全員の横棒のアニメーション（約 20 秒）で見せる。再生の途中で同じポイントの人は同じ順位にし、最後は今のランキングと同じ並び・順位になる。
  - 景品を割り当てていれば、各行にその順位の景品を添える。
- **Trend**: 累計ポイントの推移を折れ線で見せる。全員を灰色の線で描き、選んだ人（初めは上位 10 人、10 人まで）を色付きで重ねる。

ポイントの推移は、今残っている写真・お気に入り・確定したゲームから、今の設定で組み立てる。削除した写真や外したお気に入り、確定を取り消したゲームは、過去の時点の分も含めない。ゲームの点数は確定した時刻に入る。

### 7.3 参加者の画面（イベント情報）

- ランキングは管理画面と同じ横棒、推移は上位 10 人を色付きにした折れ線で見せる。
- **名前を伏せる**: 全員（自分も）の名前・二つ名を `???` にする。
- **ポイントを伏せる**: 数字を出さず、棒・線の形だけを見せる（1 位を 100 とした割合で描く）。

## 8. 景品

| # | 要件 |
|---|---|
| G-1 | 幹事が景品（名前 1〜50 文字・画像・数量 1〜100）を登録する |
| G-2 | 景品を渡す順位（ランキングの上から何番目の人か）を、数量の分だけ割り当てる。1 つの順位に複数の景品を割り当てられる |
| G-3 | 順位は、ランキングの並び（7.1）で上から 1 人ずつ数える。紐づけを解除した人は数えない |
| G-4 | 参加者に景品を見せるかは、設定で決める（既定は見せない） |

- 渡す順位は「1, 3, 5-10」のように指定する（1〜1000 位）。同じ景品を同じ順位に重ねては割り当てられない。数量より多くは割り当てられない。
- 画像は端末で縮小（長辺 1200px）して JPEG にしてから登録する。画像は任意で、無いときは箱の絵を出す。画像を差し替える・外す・景品を削除すると、古い画像はすぐに見えなくなる。
- 景品は、画像ごと 1 つの ZIP にエクスポートし、別のイベントや環境でインポートできる。
  - ZIP には景品の一覧（名前・数量・渡す順位）と画像が入る。
  - インポートでは、取り込む前に中身を見せ、今の景品に追加するか、今の景品を消して置き換えるかを選ぶ。置き換えは、すべて取り込めてから今の景品を消す。
  - 中身が正しくない（読めない・項目が足りない・数量を超える割り当てなど）ときは、何も取り込まずに理由を出す。1 回に取り込めるのは 100 件まで。
- 参加者には、景品ごとに画像・名前・渡す順位（「1〜3 位・5 位」のように）を見せる。
  - 上位の景品から並べる（渡す順位の最も小さい順。同じなら渡す人数の少ない順）。
  - どの順位にも割り当てていない景品と、数量は画面に出さない（サーバの応答には含まれる）。
  - ランキングも見せているときは、ランキングの各行にその順位の景品を添える。

## 9. スケジュール

| # | 要件 |
|---|---|
| S-1 | 幹事がスケジュール（進行表）の項目を作る。項目はタイトル（1〜50 文字）・詳細（0〜500 文字、改行可）・開始時刻・長さを持つ |
| S-2 | 時刻は縦の時間軸の上で決める。項目をドラッグすると開始時刻、下の端をドラッグすると長さが変わる（5 分刻み） |
| S-3 | 参加者にスケジュールを見せるかは、設定で決める（既定は見せない） |
| S-4 | 参加者には、今の時間の項目を「いま」、次の項目を「つぎ」として目立たせる |

- 時刻は 1 日の中（0:00〜24:00）で決める。長さは 5 分以上で、終わりは 24:00 まで。日付をまたぐ項目は作れない。
- 時間が重なる項目も作れる。管理画面では横に並べて表示する。
- 管理画面の操作
  - 空いている所を押すと、その時刻（5 分刻み）に長さ 30 分の項目を作る編集画面が開く。「項目を追加」では、最後の項目の終わりの時刻で作る。
  - 項目を押す（キーボードでは Enter）と編集画面が開き、タイトル・詳細・開始時刻・長さを直したり、削除したりできる。
  - 10 分以下の短い項目は、下の端をドラッグして長さを変えられない（編集画面で変える）。
  - 時間軸は、項目の前後に 1 時間の余白を取って表示する。「前に 1 時間広げる」「後ろに 1 時間広げる」で広げられる。
- イベントの日付（任意）を決められる。
- 参加者の画面
  - 「イベント情報」に「スケジュール」として、開始時刻の早い順に、時刻（「18:00〜18:15」）・タイトル・詳細を出す。日付があれば一覧の上に出す。
  - 端末の時計で、今の時間にかかる項目に「いま」、まだ始まっていない項目のうち最も早く始まるものに「つぎ」を付け、終わった項目は薄くする。同時に始まる・重なる項目は、どれにも付ける。
  - 日付を決めていればその日だけ「いま」「つぎ」を付け、ほかの日は付けない。日付を決めていなければ、毎日の時刻で付ける。
  - 画面を開いている間は、30 秒ごとに付け直す。

## 10. 参加者への公開設定

設定によって、参加者に見えるものは次のように変わる。

| 設定 | 既定 | オンのとき | オフのとき |
|---|---|---|---|
| ホームにポイントを表示する | オン | ホームにポイント・お気に入りに選ばれた数、「みんなの写真」に ♥ の数を出す | 出さない |
| ホームにゲームの点数を表示する | オン | ホームにゲームの点数と、点数が入ったものを出す | 出さない |
| お気に入りの選択を受け付ける | オン | お気に入りを付け外しできる | 付け外しできない（付いた分は残る） |
| 参加者にランキングを見せる | オフ | イベント情報にランキングを出す（名前・ポイントを伏せる設定あり） | 出さない |
| 参加者にポイントの推移を見せる | オフ | イベント情報に推移を出す（名前・ポイントを伏せる設定あり） | 出さない |
| 参加者に景品を見せる | オフ | イベント情報に景品を出す | 出さない |
| 参加者にスケジュールを見せる | オフ | イベント情報にスケジュールを出す | 出さない |

- 画面下の「イベント情報」は、スケジュール・ランキング・推移・景品のどれかを見せる設定のときだけ出す。複数見せるときは、画面の上部で切り替える（スケジュールが先頭）。
- オフにしたもの（スケジュール・ランキング・推移・景品、ホームのポイント・ゲームの点数）は、画面だけでなくサーバからも返さない。
- ホームのポイント・ゲームの点数を伏せても、ランキング・推移を見せていれば、そちらではポイントが見える（5 章）。発表まで隠したいときは、ランキング・推移も見せないか、「ポイントを伏せる」をオンにする。

## 11. データの初期化

- イベントの後やリハーサルの後に、本番のデータをすべて消して、デプロイ直後の状態に戻せる。
- 消えるもの: 参加者、QR コード（通し番号も 001 から）、写真、お気に入り、ゲームと答え、景品と画像、スケジュール、設定（既定値に戻る）。
- 消えないもの: アプリ本体と、ログインの仕組みに使う鍵。幹事のログインも残る。
- 初期化は管理画面からはできない。運用担当者が行う（管理者パスワードを知っているだけでは消せないようにするため）。手順は [初期設定・デプロイ手順](setup.md#本番データの初期化)。
- 元に戻せない。QR コードは印刷し直しになる。

## 12. 制約・決まっていないこと

### 12.1 扱わないもの

- 写真の保存期間・ダウンロード・肖像権の同意の取得（別途検討）
- QR コードの紛失・盗み見への対策（紐づけた後も、QR コードで何度でもログインできる。QR コードを使えなくする機能はない）
- 幹事の多要素認証（管理者パスワードは 1 つ）

### 12.2 決まっていないこと

| # | 内容 | 状態 |
|---|---|---|
| O-1 | 写真の保存期間・ダウンロードの可否・肖像権の扱い | 別途検討 |
| O-2 | 独自ドメインを使うか | 未定 |
| O-3 | 1 人あたりの写真の投稿数に上限を設けるか | 要確認 |
