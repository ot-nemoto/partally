# セキュリティ対策

partally で行っているセキュリティ対策の一覧。何を、どう守っているかをここにまとめる。細かい仕組みは [設計書](design.md)、手順は [初期設定・デプロイ手順](setup.md) に書いてあるので、ここからはそちらへ案内する。

セキュリティに関わる変更（認証・権限・秘密の値・公開範囲・ログに出すもの など）をしたら、この資料も直す。

## 1. 守るもの・前提

- **守るもの**
  - 参加者の情報（名前・二つ名・暗証番号・投稿した写真・お気に入り・ゲームの答え）
  - 公開前の写真（幹事が確かめる前の写真）と、景品・ゲームの画像
  - 管理者の操作（参加者の紐づけ解除、写真の承認・削除、ゲームの開催、設定、データの取り込み）
  - AWS のアカウントとリソース（料金を含む）
- **前提**
  - リポジトリは公開している。コード・Issue・Actions のログは誰でも読める。
  - 本番の URL は公開しない（参加者には QR コードで渡す）。ただし、URL を知られても守れるように作る。
  - 管理者は少人数（幹事）で、パスワードを 1 つ共有する。
  - AWS のアカウントを使うのは運用担当者だけ。

## 2. 参加者の認証

| 対策 | 内容 |
|---|---|
| QR コードのトークン | 128 ビットの乱数（`randomBytes(16)`、base64url で 22 文字）。推測できない。形式の違うものは受け付けない |
| 暗証番号 | 4 桁。初回の登録で決め、ログインしていない端末で QR を読み込むと聞く。scrypt（ソルト付き）でハッシュにして保存し、番号そのものは残さない |
| 暗証番号の総当たり | 5 回間違えるとロック。試す前に回数を数える（DynamoDB の条件付き更新）ので、同時に送っても 5 回までしか試せない。幹事が管理画面で解除・消去できる。ロックは時間では解けない（時間で解けると、4 桁の番号を時間をかけて試せるため）。他人の QR を手にした人がわざと間違えてロックすることはできるが、ログインしたままの端末は使え、幹事がすぐ解除できるので、そのままにしている（#222） |
| セッション | `session` Cookie（`{uid, tok, iat}` を HMAC-SHA256 で署名）。`HttpOnly; Secure; SameSite=Lax`、30 日。署名が合わない・期限切れは未ログイン |
| 紐づけ解除 | Cookie に QR のトークン（`tok`）を入れ、毎回ユーザの今のトークンと比べる。幹事が紐づけを解除すると、その人の Cookie はすべて使えなくなる |
| 比較 | 署名・パスワードの比較は定数時間（ハッシュにしてから `timingSafeEqual`）で行い、時間差から推測させない |

詳しくは [設計書 4.1](design.md#41-参加者)・[5.1](design.md#51-qr-ログイン--初回登録)。

## 3. 管理者の認証

| 対策 | 内容 |
|---|---|
| パスワード | 1 つの管理者パスワード（`PARTALLY_ADMIN_PASSWORD`）。20 文字以上のランダムな値にする（[決め方](setup.md#a-2-github-の-environment-設定)） |
| 呼び出しの上限 | `POST /api/admin/login` だけ API Gateway のルートを分け、毎秒 5 回・一度に 10 回までにする |
| 試行回数の制限 | 15 分ごとの区切りの中で、接続元（CloudFront が渡す閲覧者の IP）ごとに 10 回、全体で 50 回まで。超えると区切りが終わるまで断る（合っていても断る）。試す前に数える |
| 制限の解除 | 待つ（15 分以内）、別の回線から入る、GitHub Actions の「Unlock admin login」（[手順](setup.md#管理者のログインの制限の解除)） |
| セッション | `admin_session` Cookie（`HttpOnly; Secure; SameSite=Strict; Path=/api/admin`、12 時間）。署名鍵はセッションの鍵と管理者パスワードから作るので、パスワードを変えると、それまでの管理者の Cookie（盗まれたものも）はすべて使えなくなる（[変え方](setup.md#管理者パスワードの変え方)） |
| 管理者の API | `/api/admin/*` はすべて、ほかの処理より先に管理者の Cookie を確かめる（ログイン・ログアウトを除く） |
| できないこと | 本番データの初期化は管理画面からはできない（パスワードを知っているだけでは全部を消せない）。GitHub Actions からだけ行う（[7 章](#7-aws-の構成)） |

詳しくは [設計書 4.2](design.md#42-管理者)。

## 4. CSRF・入力の確かめ・XSS

- **CSRF**
  - 更新の API（GET・HEAD 以外）は `Content-Type: application/json` だけを受け付ける。ほかのサイトから JSON を送るにはプリフライトが要り、許していないので送れない。
  - Cookie は `SameSite`（参加者は Lax、管理者は Strict）なので、ほかのサイトからの送信には付かない。
- **入力の確かめ**
  - API が受け取る値は、すべて zod のスキーマ（`packages/shared/src/schemas.ts`）で形・長さ・範囲を確かめる。合わなければ 400。
  - 文字列は NFKC で正規化し、前後の空白を除いてから確かめる。
  - データの取り込み（ZIP）は、読む前（50MB）と展開するとき（1 ファイル 20MB・合計 200MB）に大きさを確かめ、各件を作成と同じスキーマで確かめる。1 件でも合わなければ何も取り込まない。
- **XSS**
  - 画面は React で、値はすべてエスケープして出す。`innerHTML` などの HTML をそのまま入れる書き方は使わない。

## 5. 写真・画像

| 対策 | 内容 |
|---|---|
| 非公開のバケット | 写真・画面の S3 バケットは公開を禁止（Block Public Access）し、HTTPS 以外を断る。CloudFront からだけ（OAC）読める |
| 公開済みの写真 | CloudFront の署名付き Cookie が無いと見られない（403）。Cookie は `/photos/approved/` だけに付き、12 時間で切れる。ログインした参加者にだけ発行し、アプリを開くたびに更新する |
| 確認待ちの写真・景品の画像 | 1 時間で切れる署名付き URL で、見てよい人（幹事・投稿した本人・景品を見せる設定のときの参加者）にだけ渡す |
| 署名の鍵 | CloudFront の秘密鍵はデプロイのときに作り、SSM の暗号化パラメータ（SecureString）に置く。CloudFormation のテンプレートには公開鍵だけが入る |
| アップロード | S3 への署名付き POST。5 分で切れる。大きさ（写真 5MB・サムネイル 500KB・景品の画像 2MB）、`Content-Type: image/jpeg`、投稿者（メタデータ）を条件にする |
| アップロードの上限 | 1 人あたり、確認待ちの写真は 30 枚まで、アップロード枠の発行は 10 分ごとに 30 回まで。保存先の容量・料金を増やされたり、確認待ちの一覧を埋められたりしないようにする |
| 取り込みの確かめ | 届いた写真は、受け口（`uploads/`）からサーバが確かめてから移す。投稿者が参加中であること、サムネイルと本体の投稿者が同じであること、どちらも先頭が JPEG の形式であることを確かめる。一度使った写真の ID は受け付けない（署名付き POST の使い回しで、確かめた後の写真を差し替えられないように） |
| 受け口の掃除 | 受け口に残ったものは 1 日で消す |
| 公開の方法 | 既定は「幹事が承認してから公開」。承認するまでほかの参加者に見えない |
| 削除 | 写真や画像を消したら、CloudFront のキャッシュも消す |

詳しくは [設計書](design.md) の写真のフロー。

## 6. 通信と応答のヘッダ

- 画面は HTTP を HTTPS に転送し、API・写真は HTTPS だけを受け付ける。
- API は CloudFront を通ったリクエストだけを受ける。CloudFront が秘密の値を `X-Origin-Verify` ヘッダで付け、API はこれが合わないリクエスト（API Gateway の元の URL に直接送られたもの）を 403 で断る。応答のヘッダや、接続元（管理者のログインの試行回数を数えるのに使う）を迂回・偽装させないため。
- CloudFront で、すべての応答にセキュリティ用のヘッダを付ける（HSTS、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: same-origin`、CSP の一部）。
- 読み込み元を絞る CSP（スクリプト・スタイル・フォントは自分のサイトだけ、など）を Report-Only で付け、違反を `/api/csp-report` で CloudWatch Logs に残す（参加リンクのトークンは伏せる）。ログで違反が出ないことを確かめてから効かせる（#227）。
- 参加リンク（`/q/<トークン>`）の URL にはトークンが入るので、`Referrer-Policy` でほかのサイトへ URL を送らない。

詳しくは [設計書 8.2](design.md#82-応答のヘッダセキュリティ)。

## 7. AWS の構成

| 対策 | 内容 |
|---|---|
| 秘密の値の置き場所 | 管理者パスワード・セッションの署名鍵・CloudFront の秘密鍵・`X-Origin-Verify` の値は、SSM の暗号化パラメータ（SecureString）に置く。CloudFormation のテンプレートと Lambda の環境変数には、パラメータの名前だけが入る。管理者パスワードは GitHub の Secret から、デプロイの CI が書き込む（GitHub Actions のロールは書き込めるだけで、読めない） |
| 権限 | Lambda ごとに要る権限だけを与える（テーブルの読み書き、バケットの読み書き・削除、特定のパラメータの読み取り、特定のディストリビューションの無効化）。初期化の Lambda は写真の中身を読めない（一覧と削除だけ） |
| 呼び出しの上限 | API Gateway のステージ全体で毎秒 200 回・一度に 400 回まで（使いすぎの歯止め）。管理者のログインは別に毎秒 5 回 |
| 本番データの初期化 | GitHub Actions の Reset ワークフローからだけ行う。確認欄に「初期化」と入れないと止まり、Lambda も決まった合言葉付きの呼び出しでなければ何もしない（[手順](setup.md#本番データの初期化)） |
| 誤削除の防止 | DynamoDB のテーブルと写真のバケットは、スタックを消しても残す（RETAIN） |
| ログ | Lambda のログは 1 か月で消す |
| 料金 | 予算アラート（任意）で、使いすぎに気づけるようにする（[手順](setup.md#予算アラートを有効にする)） |

## 8. CI/CD と公開リポジトリ

| 対策 | 内容 |
|---|---|
| AWS への入り方 | GitHub Actions の OIDC でロールを引き受ける。長く使えるアクセスキーは置かない。ロールの信頼ポリシーで、このリポジトリの `production` Environment のジョブだけに絞る（リポジトリ・オーナーの ID まで含めて、同じ名前で作り直されたリポジトリからのなりすましも防ぐ） |
| ロールの権限 | CDK のデプロイ用ロールを引き受けること、初期化の Lambda を呼ぶこと、管理者パスワードの SSM パラメータに書き込むことだけ |
| デプロイできるブランチ | `production` Environment は `develop` だけに限る。`develop` への反映には PR のマージが要る |
| 秘密の値 | 管理者パスワード・ロール ARN・予算の通知先は Environment secrets に置く（ログで伏せられ、デプロイのジョブからしか読めない） |
| ログに出さないもの | アカウント ID、ロールの ID、本番の URL、バケット名・テーブル名、スタック ID。認証は自前の action（`.github/actions/aws-oidc`）で行い、受け取った値は伏せてから使う。`cdk deploy` の Outputs も表示しない。デプロイ先は、ジョブのまとめに出す CloudFormation コンソールのリンクから確かめる |
| PR の CI | PR の CI（lint・型チェック・テスト・E2E）は秘密の値を使わない。デプロイは `develop` への push だけ |
| ほかのリポジトリからの PR | バージョンを上げるワークフローは、同じリポジトリの PR でだけ動く |
| 外部のアクション | GitHub 以外が作るアクションは、コミットの SHA で固定する（タグの付け替えで中身を差し替えられないように）。GitHub 公式（`actions/*`）は版の番号で指定する。テストで確かめる（[開発ガイド](development.md)） |
| 依存の更新 | Dependabot が毎週、npm と GitHub Actions の更新の PR を作る。`npm audit` の指摘は、本番に含まれないビルド用の依存でも更新して解消する |
| リポジトリに書かないもの | AWS のアカウント ID、ロール ARN、メールアドレス、パスワード、実際のドメイン（[CLAUDE.md](../CLAUDE.md)） |

詳しくは [初期設定・デプロイ手順 A](setup.md#a-github-actions-からデプロイ推奨)。

## 9. 運用で気をつけること

- 管理者パスワードは 20 文字以上のランダムな値にし、幹事の間だけで共有する。漏れたかもしれないときは変える（[変え方](setup.md#管理者パスワードの変え方)。それまでの管理者のログインはすべて切れる）。
- QR コードと参加リンクは、1 枚が 1 人分のログインになる。人に見せたり渡したりしないよう案内する。なくした・渡してしまったときは、幹事が紐づけを解除する（[幹事向けガイド](organizer-guide.md)）。
- 写真は、既定の「幹事が承認してから公開」のまま使う。「アップロードと同時に公開」にすると、確かめる前の写真がすぐに全員に見える。
- イベントが終わったら、要らなくなったデータは初期化で消す（[手順](setup.md#本番データの初期化)）。
